# 15 个上场身份

> **权威：** 完整 43 人名册、每派 8 人与跨派关系以 [design/characters/roster.md](../design/characters/roster.md) 为准；本文只定义**序章切片实际上场的 15 人**、他们的运行 ID 与人格契约。
> 数量口径见 [00-scope-and-invariants.md](../00-scope-and-invariants.md) 第 1.1 节。

## 1. 编制

每局 **15 个自主身份**：

| 组 | 人数 | agentId 规则 | 说明 |
|---|---:|---|---|
| 本派支持者 | 8 | `npc-<拼音>` | 玩家占公社席时，名册第 1 行转为资深支持者，其余 7 人一起上场 |
| AI 党魁 | 4 | `<factionId>` | 其余四派只创建党魁；该派 7 名支持者不实例化 |
| 外域 Agent | 3 | `species-*` | 巡裔、根庭、泊星者各一名最高决策者 |

- 玩家是独立 principal（`player-1`），不是第 16 个 Agent；玩家占 `seat.commune`。
- 43 名册中未上场的 28 人仍然存在：以简报署名、传闻来源、证人、替补与编年史出现，不调用模型。
- **AI 党魁不是另一个 `npc-` 身份。** 岑雁上场时 `agentId = human-independent`；不允许 `human-independent` 与 `npc-cenyan` 同时行动。玩家占公社席时，公社的 AI 党魁不创建，闻昭以 `npc-wenzhao` 上场。
- 模型数量不等于 Agent 数量：一个模型可以承载多个身份，但每个身份有独立目标、记忆、知情与行为权限。

**态势的用法：** 表中的“初始态势”是设计 8 人支持系统的基线；序章不运行支持/吞并算法，它只作为 Agent 对玩家提议的默认倾向与执行系数参考，不产生“支持崩解”或“吞并”结算。

| `npc-taoan` | 陶安 | 工务长 / 工程 | 能修的东西就不要拆 | 观望 | 你给足材料，不逼他赶工 | 参与过一段偷工减料的城墙 |

## 5. 未上场的 28 人怎么用

| 用途 | 例子 | 规则 |
|---|---|---|
| 剧情卡署名 | 沈砾署名中继警报、苏回署名求援、谷寻向公社发请求 | 署名不代表实例化；卡片效果直接产生事件，不调用该角色模型 |
| 传闻来源 | 商贩、边环居民、无名信使 | 用 `reported` 渠道；规则不判断真假 |
| 证人/证据持有人 | 档案记录、旧账本、闸门日志 | 通过证据与知识授权出现 |
| 替补 | 某派支持者死亡/离开后，从同派名册第 2–8 行或新 NPC 补位 | 补位者不继承死者记忆 |
| 编年史 | 结局、遗产局、派系关系变化 | 只读文本，不参与结算 |

**一条硬规则：** 28 人不上场，但**不能写成没有决策能力的静态姓名**。他们一旦被写进对话、证据或剧情卡，就必须有立场、底线与可追溯的来源；只是不调用模型。

## 6. Persona 内容契约

角色定义分三组字段：

| 组 | 字段 | 约束 |
|---|---|---|
| 身份 | `agentId`、`characterId`、`factionId`、角色类型 | ID 不改名；改名必须升 `contentVersion` 并写迁移 |
| 能力与取向 | 岗位/技能、价值取向、表达特征、底线、目标 | 底线不能被一次对话临时绕过 |
| 关系与初始信息 | 初始关系、初始已知来源、出生/驻地节点 | 初始关系是版本化基线，不是运行中的记忆 |

- 装配引用（`profileRef`、`toolsetRef`）写在 `config/rosters/`，不写进人格。
- 人格不含 provider/model/temperature/API key，也不含可执行脚本。
- 稳定身份与可变状态分离：任免、受伤、转派不重置人格与记忆；新任务不是新角色。

## 8. 人格与行为验收

1. **同一请求至少三种可辨别倾向。** 例如向岑雁要护送：担保后同意、只给路线不给队、要求先交付再谈。
2. **变化必须有依据。** 不能因为玩家说了漂亮话就从“戒备”变“坚定”；要有兑现、证据、共同经历或明确交换。
3. **拒绝要给条件。** 拒绝时应给出替代方案、底线或下一次机会，不能只说“不”。
4. **秘密不等于公开。** 角色知道秘密也未必有权转述；`releasePolicy: private` 的内容不能主动说原文。
5. **评估分开看。** 人格一致性、记忆事实、行为合法性分别评估，不能用固定台词判定“像人”。

每角色至少准备五组场景：无经历基线、正向共同经历、违约/误会、反证、主动任务。详细约束见 [感知](../agent/perception.md)、[记忆](../agent/memory.md) 与 [运行时](../agent/runtime.md)。
