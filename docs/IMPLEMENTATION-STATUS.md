## 2. 本次已对齐

1. **名册与身份**：新增 `config/rosters/standard-15.yaml`，同步 `core-3`、`.env.example`、`config/runs/online-default.yaml` 与服务端默认 `rosterRef`。单人正式名册的 schema 上限改为 15。
2. **内容包 0.2.0**：`factions.yaml` 拆分为 `factionHomeNodeId`、`outpostNodeId`、`territoryNodeId`，并补上党魁、秘密与关系；`characters.yaml` 对齐 8 名公社支持者和 3 名外域 Agent，新增 `characterId` 与 `secret`；`starts.yaml` 只启用公社席，并补上闻昭的第三条开局消息；`world-init.yaml` 的职责委托改用党魁运行身份；`evidence.yaml` 清理旧身份持有者；`locale/zh-CN.yaml` 的玩家称呼改为“党魁”并补齐材料、食物、水词条。
3. **剧情卡署名**：把青枝、洛、追风、唐箴的署名改为 `species-flora`、`species-extraterrestrial`、`species-fauna`、`human-pacifist`；沈砾、苏回、谷寻保留为 signature-only 署名，不实例化。内容加载器、剧情模块与剧情卡校验共用同一份名单。
4. **时钟与章节终点**：20 秒/tick 写入时钟模块默认值与三份装配。章节评估步骤在 t168 返回停止请求，tick 收尾后暂停时钟；tick 169 被拒绝，存档保留。
5. **公社玩家权限**：玩家会话可以提交 `watergate.allocation` 的 `policy.set`，处理器按 campaign 的 `playerId` 与 `factionId` 裁决；其他派系党魁返回 `no-authority`。`water-allocation` 条款允许玩家 `player-1` 作为义务人，改策违约按 `PolicyChanged.byId` 记到协议。
6. **任务规则身份**：任务加成从旧角色 ID 迁移到 15 人编制：穆枝参与救援减 2 tick，祁录或追风参与侦察每条道路减 1 tick，陶安参与修复 +10，洛参与非 `team-star` 修复 +15，陆沉或追风参与迁徙道路护送 +4。救援参与人允许在医疗目的地节点加入。

## 3. 剩余迁移项

### 3.1 身份配额

部署级共享配额还没有落到激活事务。Agent 运行时接入后，需要在同一事务里检查在线、实验与探针分支的活动身份总数；达到 15 后拒绝第 16 个身份，释放名额后可重新激活。分支切换、暂停身份与存档恢复都要沿用同一计数。

### 3.2 t168 资源交接

序章只结算 `supply`、`energy`、`medical`；`materials`、`food`、`water` 在 t168 按设计初值起算。当前 `ResourceId`、库存契约与玩家投影只有三种资源，评估事件也不带交接数据。补齐时需要同步公共契约、内容初值、库存聚合、投影与测试，不改写序章已发生的消耗。

### 3.3 t144 程序案

需补齐提案与投票命令、五席授权、`MotionDecided` 公共事件与感知模板、议事录、玩家投影及其词条，并把结果写进 t168 评估。表决截止和缺席结案时点仍待定稿，未定稿前不实现猜测性的部分。参见 [domain-model.md — 命令目录](architecture/domain-model.md#5-命令目录)、[perception.md — 观察内容](agent/perception.md#114-观察内容)。

### 3.4 玩家公开广播

规则要求公社党魁可以以玩家身份提交广播正文，复用 comms 的送达规则。命令名、正文长度与提交入口尚未定稿；当前玩家命令白名单没有广播类命令，事件契约也没有对应的玩家命令。定稿后经命令网关提交 `MessageSent`，与 Agent 的安全对白流程保持独立。

### 3.5 席位契约

补齐 `seatId` 与 `actorId` 的持久记录、会话授权、命令、事件、投影和存档回放。先定稿存储与接口字段，验证人类席位归属、外域与系统来源、多席表决和既有记录兼容读取。参见 [contracts.md — 契约演进](architecture/contracts.md#7-契约演进)。

### 3.6 时钟操作原子性

暂停与继续当前在时钟状态提交后单独写入 `operationId` 结果，进程在两次提交之间退出时重试可能出现版本冲突。需要补齐原子性并验证崩溃后的同键重试。参见 [operations.md — 时钟与运行状态](platform/operations.md#2-时钟与运行状态)。

### 3.7 表现与认知管线

客户端、控制台页面、Agent 运行时、模型池与记忆模块仍按构建计划 S10–S21 推进。灰盒只证明交互与可读性；3D 资产按 [design/assets/02-modeling-spec.md](design/assets/02-modeling-spec.md) 单独验收。

## 4. 迁移顺序

| 交付内容 | 范围 | 完成判据 |
|---|---|---|
| 身份配额 | 部署级 15 个活动身份的配额 | 达到配额后第 16 个身份激活被拒，释放后可重新激活 |
| 章节交接 | 六种资源在 t168 的初值与投影 | 评估事件带交接数据，冻结分支可复算 |
| 程序案与章节评估 | t144 表决、议事录与 t168 评估关联 | 表决、投影、章节结果及存档恢复均有验证 |
| 席位契约 | 命令、事件、投影、存档的席位归属 | 恢复和回放保留席位与实际动作者 |
| 客户端与控制台 | 玩家灰盒、控制台页面与运营接口 | 两个本地端口内的交互与权限验收 |
| 认知管线 | Agent 运行时、记忆与模型路径 | 三核心角色端到端验证通过 |

**不要做的事：** 不要为了“先跑起来”恢复 20 人运行名册，或让五席开局重新对玩家开放；也不要用配置默认值掩盖缺失的配额与席位契约。
