# 垂直切片与验收

> **权威：** 目标验收见 [design/gameplay/05-chapter.md](../design/gameplay/05-chapter.md) 与 [16-campaign-arc.md](../design/gameplay/16-campaign-arc.md)。本文是 **序章切片**（15 Agent、3D 目标 + 2.5D 灰盒、七日）的验收；冲突时以设计和 [00-scope](../00-scope-and-invariants.md) 为准。

> 状态：目标计划，不是完成报告。本文定义切片与验收标准；逐步实施的顺序、每一步要建的文件与完成判据见 [构建计划](build-plan.md)。首版交付范围为 A 到 C 与 M（全模块可插拔与双端验收）；D 是之后的扩展方向，不要求首版为每个维度都实现两种策略。范围与数量以 [00](../00-scope-and-invariants.md) 为准。

## 1. 交付原则

每个切片都从玩家输入走到合法世界结果，再回到 NPC 后续选择；只展示 prompt、最终台词或静态地图不算可玩切片。玩法以交涉、证据、承诺与协作为主，轻数值规则提供真实约束。

技术起点是 TypeScript 全栈、React HUD、独立场景适配层（PixiJS 2.5D 灰盒；3D 渲染器实现同一 `SceneRenderer` 端口）、Node 和 SQLite 单写者。依赖版本在实现时验证锁定，不能把目标目录、设计阈值或本文验收项写成已实测能力。

首版单玩家，一个在线权威世界。标准 **15 个 Agent** 为 8 名公社支持者、4 名 AI 党魁、3 名外域 Agent；在线与实验活动身份合计最多 15。每个实验 run 独占 branch，满员实验先暂停在线运行并释放实例，再逐变体执行。

只有两个本地端口：玩家客户端 `:5173` 与服务端 `:3000`；控制台复用服务端端口的 `/console/*`，不新增第三监听。基础宿主保留模块注册/能力图/生命周期/guard/证据/冻结；游戏、Agent、平台、客户端与控制台具体职能均由模块提供。

每步交付包含可运行场景、确定性工程断言、生成式行为观察和可追踪 artifact。工程正确性必须可重复；远程模型的逐字输出不作为确定性断言。

## 2. A：三核心角色的 TS / 灰盒双端闭环

范围：岑雁、林芜、乔述，六节点地图，单玩家沙盘，一组共享模型/工具，运输或救援行动与一项有后果的承诺；两个本地端口、server/client/console 三个宿主、最小模块装配与最小控制台页面。

先用确定性 decision adapter 与 deterministic model transport 验证事务和链路，再接真实模型。model、memory、perception、context、game 规则与 client UI 均通过公共 ports 装配，不能以“先做 demo”为由把直接 SDK 调用或世界写库塞入 UI。

| 场景 | 通过条件 | 证据 |
|---|---|---|
| 双端启动 | `:5173` 玩家页面与 `:3000/console` 控制台均可访问；无第三监听 | 启动日志、端口监听检查 |
| 点选与交涉 | 节点/人物可点选，HUD 展示任务和承诺，玩家可发起对话 | 灰盒点选、HUD 与交谈记录 |
| 移动与任务 | 服务端确认路线/行动后展示运动；完成只由规则事件决定 | command、receipt、任务事件及场景变化 |
| 意愿与后果 | NPC 可拒绝/提出条件；承诺结果进入后续互动 | 至少一条有来源的行为变化链 |
| 暂停与单步 | paused 时 tick 不推进、候选不晚到提交，单步有界 | 时钟、turn epoch、任务状态断言 |
| 保存与恢复 | 重启后位置、预留资源、任务和记忆恢复，不重复结算 | 一致快照与恢复前后差分 |
| 控制台最小 | 模型挂载、运行总览、trace 查看可用；玩家会话访问控制台 API 被拒 | 控制台页面记录、403 断言 |

同一请求重试不会重复派遣或占用物资；玩家与 NPC 同时争用资源时只有合法请求成功。视口缩放不改变 world 坐标、可达性或授权；无渲染 adapter 能执行同一规则场景。

退出条件：从玩家 command 可追踪到事实、observation、memory/context、最终模型请求、工具 receipt、世界结果与后续交谈；两个端口与三 realm 边界成立。A 只证明闭环成立，不证明某记忆策略更好。

## 3. B：四类 memory 的可比较实验

范围固定为 M0 memory.none、M1 memory.ledger、M2 memory.stream-reflection、M3 memory.layered-hybrid。M0 以 baseline-window 为主要基线，baseline-current 仅作诊断；具体语义见 [memory](../agent/memory.md)。

三核心角色继续作为受控场景载体。固定开局、原始观察、当前投影、会话窗口、模型挂载、工具、预算及其他槽；变体独占 branch，按共同逻辑恢复点启动。

| 多轮问题 | 至少验证的差异与来源 |
|---|---|
| 承诺间隔与到期 | 是否记住对象、条件和截止，是否主动提醒/行动 |
| 兑现与背弃 | 后续合作条件是否随已知经历变化，原因能否定位 |
| 二手传闻与反证 | 是否区分“听说”与已验证，是否保留来源并修正印象 |
| 主体与保密隔离 | 某角色知道的秘密不会被其他角色召回或公开传播 |
| 容量/召回预算 | 候选、过滤、排序、最终入模及 token 是否分别可见 |
| 重投与后台整理 | 重复观察不重复强化，过期维护 CAS 不覆盖新 revision |

冷启动、共同历史重建和兼容状态导入必须分开声明；不能把不兼容状态直接复制给新算法。原始审计历史不因 memory 遗忘被删除，也不能从其他槽悄悄补回 M0。

严格实验中缺必需水位、插件失败或关键 artifact 缺失时判 failed/invalid；无效数量进入分母说明，不用 fallback 输出填补成功样本。开环和闭环报告分别解释输入是否继续相同。

退出条件：四组均有独立运行证据、实际 effective 参数、多轮行为和成本报告。可以得出“证据不足/差异不显著”，不能为了呈现梯度手工调整台词或删除失败样本。

## 4. C：完整首版与可维护扩展

范围：完整 **15 个身份**（8 名公社支持者 + 4 名 AI 党魁 + 3 名外域）、只开放公社席、同一序章“水闸之前”、三个外域可选真人接管、集中模型池与共享工具绑定、两个端口上的完整玩家和控制台产品。设计支持五席；本切片只交付一席，其余四席按 AI 党魁运行。

| 验收项 | 通过条件 |
|---|---|
| 单席开局 | 公社席进入序章地图/规则；初始授权、消息和 8 名支持者接触有初始化来源；另外四席以 AI 党魁运行 |
| 公社玩家命令 | 玩家能设置水闸分配、承担水闸条款义务并发公开广播。服务端依当前 campaign 裁决权限，记录实际动作者 |
| 15 个身份 | 8 名支持者、4 名 AI 党魁、3 名外域均有接触机会、有后果的互动和独立记忆；不把同一人物拆成 `npc-` 与 `factionId` 两个身份 |
| 党魁与支持者分工 | 派系意见经合法消息传达；支持者可按职责与经历协商，不共享脑内上下文 |
| 主动世界 | 合法事件、消息、承诺到期能触发主动提案；无无界逐 tick 全员推理 |
| 三势力导演 | 三席位可独立 agent/human；接管保持身份，旧 epoch 候选和排队调用被拒绝 |
| 集中模型配置 | 一次定义 modelId 后通过 mounts 挂载多个 Agent/purpose，roster 无 provider/model 副本 |
| 共享工具 | 一个 ToolDefinition 实现多主体绑定；各自授权/预算/trace 独立，副作用统一 command |
| 资源上限 | 第 16 个活动 gameplay 身份被拒绝/排队；辅助调用不产生隐藏子 Agent |
| 序章边界 | 只结算供给/能源/医疗；材料/食物/水在 t168 按设计初值出现，不追溯序章消耗 |
| t144 表决 | 五席各 1 票、3 票通过；玩家能投本派一票，四名 AI 党魁按立场投，结果写入议事录 |
| 表现目标 | 3D 斜俯视是目标；2.5D 灰盒只验证交互与可读性，不作为美术验收 |
| 内容运营 | 事件卡草稿不可感知，发布幂等；生效后修正通过补偿，调试覆盖标污染 |
| 控制台产品 | 模型挂载、三势力运营、可观测、可评估、可调试、模块装配页面均可用且权限隔离 |
| 玩家设置 | 设置模块可替换、可恢复默认；测试 preset 只能申请新 run/branch |
| 双端边界 | 只有 5173/3000 两个监听；浏览器不持密钥、不直连数据库、不能绕服务端写世界 |

完整 roster 下测量队列积压、端到端延迟、模型/工具次数、token、费用和恢复耗时。记录部署条件与失败率；15 个身份不等于 15 路同时推理，也不构成性能承诺。

退出条件：A 到 C 的工程断言通过，15 个身份和公社单席开局有可检查记录，四 memory 组可按同协议重跑，两个端口与控制台权限边界不串；M 的全模块替换证据齐备。

## 5. M：全模块可插拔与双端验收（首版核心）

M 是本项目的核心验收，不是可有可无的附加实验：基础宿主保留，游戏、Agent、客户端、服务端平台与控制台职能均能通过模块替换改变，且不修改无关消费者。

| 替换对象 | 只改什么 | 必须保持不变 | 通过证据 |
|---|---|---|---|
| 剧情推进（game 规则）：`game.scenario.watergate` → `game.scenario.watergate-escalating` | 模块实现 + assembly + 配置 | 世界命令/事件 schema、客户端协议 | 同一受控 tick 与命令脚本下，卡片触发时刻与指标的差异可解释；无关消费者源码未改 |
| 地图/通行 provider | game.map 模块 + 内容 pack | 客户端坐标与 command 语义 | 同一 command 的授权路径/拒绝原因与版本记录 |
| 客户端 HUD：`client.hud.standard` → `client.hud.compact`（另用 null renderer 跑规则场景） | client 模块 + client assembly | 服务端投影、世界结果 | 同一 player command 结果不变；无渲染 adapter 可跑规则场景 |
| 控制台观测页：`console.observability.standard` → `console.observability.lite` | console 模块 + console assembly | trace/评估数据生成与权限 | 同 traceId 可查；玩家会话仍 403；页面缺失不影响服务端 |
| memory / context / compression / tool-view | 对应模块 + profile/variant | runtime、世界规则、客户端 | 同输入实际入模差异与行为差异 |
| 模型传输或存储 adapter | adapter + assembly + 迁移 | 业务 port 与错误语义 | 重试/未知结果/事务/迁移测试通过 |
| 新增共享工具 | tools contributor + binding | 其他 Agent executor | 一次实现多处注册，越权被拒 |

| 部署/装配项 | 通过条件 |
|---|---|
| 两个端口 | 启动后只有 `:5173` 与 `:3000` 本应用监听；控制台在 `:3000/console` |
| 三个 realm | player 会话访问控制台 API 被拒；浏览器包不含服务端模块、数据库或密钥 |
| 装配校验 | 缺必需模块、能力冲突、realm 越界、slot 冲突都在 ready 前失败；可选模块缺失有可见降级 |
| 目录与清单 | catalog 快照、assembly、三 realm resolved 清单 hash 可复算并进入 run manifest |
| 设置边界 | 玩家设置只改展示/输入；测试 preset 只能申请新 run/branch |
| 拔插生命周期 | 无状态页面卸载无残余订阅；有状态模块只在暂停点替换并有状态迁移/新 branch |

退出条件：游戏规则、客户端 UI、Agent 认知、控制台页面四类各完成一次真实替换演示，每项附最小修改面 diff、契约测试和实际场景 trace。任何一项失败或未运行都如实报告，目录数量或接口数量不能代替替换证据。

## 6. D：后续独立实验轴

后续按实际问题增加 perception、context、compression、tool-view、scheduling、decision 与模型比较。先固定合法基线并验证接口；不要求 A 到 C 时为每类先造两套实现。

- context 改顺序或预算时，原始观察/记忆保持可追踪；证明差异实际进入最终序列化请求。
- compression 保留来源与损失报告，压缩后重新检查权限、tool 配对和模型窗口。
- tool-view 改变模型看到的详细程度，不能改变原始结果、隐瞒失败或重复执行副作用。
- perception 在硬权限内实验粒度、延迟和可靠性；不能把“更聪明”建立在额外读取秘密之上。
- scheduling 比较触发合并、优先级和公平性，仍受全平台身份、预算和队列上限约束。

每次新增一个明确比较问题，预注册轴、固定项、预期证据和失效条件。通过单轴定位后再研究交互，不穷举所有组合。

## 7. 必须通过的故障与竞态

| 注入点 | 正确结果 |
|---|---|
| 相同 commandId 重发/换 payload | 同请求返回原 receipt；换 payload 拒绝，不重复预留 |
| 世界事务提交后、outbox 确认前崩溃 | 重投后 inbox 去重，记忆/资源不重复生效 |
| turn 等待记忆，整理任务同时发布 | 无 actor 自锁；读取绑定冻结 revision，过期 CAS 拒绝 |
| 接管发生在模型返回前 | 旧 controllerEpoch 行动被拒绝，已接受任务不回滚 |
| 暂停发生在工具排队中 | 未提交调用取消/fence，已提交效果可追踪，不偷推进 tick |
| provider 超时/拒绝/坏 JSON | 全部 attempt 与费用留存；重试有界，严格实验不默换模型 |
| 必需 memory/索引/水位失败 | not-ready/failed/invalid，不能伪装无召回正常样本 |
| snapshot 备份或状态迁移失败 | 旧分支保留，新分支不切在线；不清库假成功 |
| 世界满员后申请完整实验 | 无额外 15 个身份；暂停在线运行并释放实例后逐分支执行 |
| researcher 真值进入席位输入 | 请求拒绝或实验标污染，不能成为角色已知证据 |
| 必需模块缺失/版本不兼容 | realm 拒绝 ready，不启动半套系统；无有效样本 |
| 可选客户端/控制台模块卸载失败 | 保留旧实例并报错，不能显示“已更换”但实际仍运行 |
| 浏览器 realm 请求服务端对象/密钥 | 请求失败并留安全检查记录，不能靠前端隐藏按钮 |

这些测试验证系统不变量，模型可用确定性 adapter 注入迟到、失败与取消；真实 provider 连通与行为评估另行记录，不用脆弱逐字断言替代。

## 8. 用一次扩展证明模块化

新增 memory 模块只修改自身实现/测试、显式 catalog 登记与 profile，必要时新增集中模型挂载；不修改世界规则或复制 turn loop。共享参数界面从描述符展示，未知参数和不兼容能力在运行前拒绝。

新增游戏职能模块只实现 port 计划/查询并更新 assembly；不 import 其他游戏模块实现，不直接写世界库。新增 client/console 页面模块只在定义中声明 slot/remote 能力并在本 realm 组合根登记；不修改 server 实现。

新增 NPC 主要新增角色内容、roster 身份及 profile/toolset/model mounts 引用；不得复制 provider 配置、工具 handler 或角色专属 runtime。标准 roster 已满 15 时使用替换/缩减 preset 验证，不将验收角色变成第 16 个活动身份。

换模型只新增或修改集中 models 条目与 mounts，保持稳定 agentId、记忆和工具权限。验证相同模型服务多个 Agent 时会话与秘密前缀仍隔离，不能通过复用远程 conversation 串读历史。

工具新增只实现一次，在多个主体注册 binding 引用；一个主体撤销授权后不能继续执行排队旧调用，其他合法绑定仍能使用共享定义。

扩展结果须展示最小修改面、相关契约测试和一个实际场景的 trace。目录变多或接口数量增加不算模块化证据。

## 9. 交付包与判定

首个正式 Demo 的发布版本定为 `0.1.0`，对应当前仓库根 `package.json` 的 `version`。

| 内容 | 最小证据 |
|---|---|
| 可运行版本 | 源码 revision、依赖锁文件、构建/启动步骤、内容/规则版本、两端口启动日志 |
| 组合 | 冻结 manifest、三 realm assembly、models/mounts 去密钥解析、工具绑定、profile diff |
| 实验 | 快照、独占 branch、输入脚本、逻辑时间、评估协议与有效性数量 |
| 因果链 | 从 command/event 经 observation、memory revision、context、model/tool、receipt 到后果 |
| 观测 | 最终请求/响应、原始工具结果及模型视图、错误、usage 和未知成本说明 |
| 模块替换 | 至少四类替换的最小 diff、catalog/assembly 快照、生命周期与状态迁移记录 |
| 双端 | 端口监听、realm 权限、控制台页面与玩家设置验收记录 |
| 质量 | 已运行/失败/跳过的检查，人工体验记录，已知限制和复现方式 |

敏感原文与凭据不进 Git；授权 artifact 以稳定引用查询。未完成的场景、未测性能和失败都如实列出，不以 UI 能打开代替通过。

达到 A 到 C 与 M 才可称为首版 Agent NPC 设计对比 demo。完成本文只表示验收标准已经写出，不表示运行时、角色可信度或任何记忆方案已经通过。
