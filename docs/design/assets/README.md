# 资产总纲

> 本目录是《炉边议会》的**资产规定**：需要哪些东西、各自多少、什么标准、先做哪一个。
> 它不是风格定义的替代品——[art-direction.md — 表现与资产方向](../../game/art-direction.md) 第 1 节管“看起来对不对”，本目录管“有没有、够不够、能不能验收”。
> 上游：[游戏概览](../game-overview.md) · [灰港城](../world/grayharbor.md) · [城建](../gameplay/08-city-building.md) · [界面](../gameplay/06-player-experience.md)

## 一、一句话

**一座能被读懂的城，和四十三张能被认出来的脸。**

玩家的主要动作是“看”：看哪片街区在冷、哪条路在堵、谁的屋顶破了、谁在食堂没来。所以资产的第一指标不是精细度，是**可读性**；第二指标才是质感。建模精良的定义在本作里是：**在 25% 缩放下仍然能认出是什么、在 100% 拉近时经得起看、在三次损坏后仍然像同一栋楼。**

## 三、四条原则

### 1. 先可读，再可信

- 每个建筑必须有一句话能说清的剪影：**炉是塔、仓是盒、温室是斜顶、矿井是井架、哨塔是细高、居所是坡顶带烟囱。**
- 屋顶形状、烟囱位置、灯光颜色是第一识别层；材质与花纹是第二层。
- 灰度测试：去掉颜色后，仍能分清居住、生产、医疗、军事、外交五类。

### 2. 模块化，不复制整栋

- 建筑由 **墙体 / 屋顶 / 门窗 / 附属（烟囱、管道、招牌、外挂楼梯）/ 地基** 五类模块拼装，1 米网格对齐。
- 三级升级不是“同一栋放大”，而是**加建**：二级加一层或加翼楼，三级加塔、加连廊、加设备。玩家要能一眼看出“这栋楼升过级”。
- 损坏态不是三套模型，而是**替换模块**：破屋顶、钉板窗、塌墙、清墟堆。同一栋楼受损后仍然是它自己。

### 3. 磨损有成因

- 锈从下往上、从铆钉往外；雪积在朝上的面；水痕在墙脚；烟熏在烟囱口。
- 任何随机污渍都要能回答“它为什么在这里”。答不出来的污渍不许上。
- 雪与湿是**材质参数**（`snowAmount`、`wetness`、`sootAmount`），不是画死的贴图；同一栋楼在四个季节要有四种状态。

### 4. 一物多用，但不糊弄

- 道具按“可搬运 / 可堆放 / 可交互”三类设计，同一件木箱在仓库、工地、车队、难民营都能用。
- 复用不等于将就：同一个桶在食堂是汤桶、在医院是污水桶、在矿场是油桶——通过**贴花与配件**区分，不换模型。

## 四、总量与优先级

| 优先级 | 范围 | 用途 | 验收 |
|---|---|---|---|
| **P0 垂直切片** | 12 类建筑、1 群系、15 个 Agent、45 道具、6 特效、60 图标 | Demo 可玩闭环 | 必须进引擎、可跑 30fps |
| **P1 首版** | 28 类地块建筑 ×3 级、43 具名角色、4 群系、120 道具、18 特效、120 图标 | 正式发售 | 全部通过[建模规格](02-modeling-spec.md#十三验收) |
| **P2 长线** | 赛季皮肤、第二座城、更多生物与载具 | 运营 | 不破坏 P1 风格 |

**P0 的 12 类建筑：** 中继炉、中继附属、居所、医务所、温室、水站、热站、仓库、矿井、工坊、哨塔、议事厅。这 12 类覆盖了“热、水、粮、料、防、政”六条读数，能撑起序章与第一周。

**P0 的 15 个 Agent：** 公社 8 人 + 岑雁、林芜、唐箴、乔述 + 追风、青枝、洛。这正是单局 15 人的编制。

## 五、与根目录 `assets/` 的关系

根目录 `assets/` 是仓库内的**第一版 2.5D 资产包**：8 枚派系徽记（`assets/factions/*.svg`）、6 张地点场景图（`assets/world/*.svg`）、地点 PNG 预览与 `manifest.json`。本轮设计改为 3D 斜俯视后，它的定位调整为：

| 现有资产 | 现在的用途 | 是否进入 3D 管线 |
|---|---|---|
| 8 枚派系徽记 | **继续使用**，作为 3D 旗帜/铜印/界面的源文件 | 是（矢量转贴花） |
| 6 张地点场景图 | 降级为**宣发/载入图/概念参考** | 否 |
| 地点 PNG 预览 | 文档与评审展示，不进入运行时 | 否 |
| `manifest.json` | 2D 包的清单、坐标与配色基准 | 否（v2 另立清单） |

**包版本：** 3D 资产另起 `packId = earth-2964-v2`，不复用 v1 的 `manifest.json` 与地块坐标；v1 继续作为 2D/宣发包存在。两者可以并存，但不共享 `contentVersion`。

**一条硬规则：** 3D 资产不得直接照搬立绘的比例。立绘是四分之三侧、头肩占比 55% 的插画构图；3D 角色要按真实人体比例建模（Hero 约 7.5 头身，巡裔 8 头身，根庭 8.5 头身，泊星者 8 头身），否则在斜俯视里会变成大头娃娃。

## 六、技术基线

| 项 | 规定 | 原因 |
|---|---|---|
| 单位 | 1 单位 = 1 米；Y 轴向上 | 与地块网格、镜头、物理一致 |
| 地块 | 每个地块是 32m × 32m 建址；内部 8m 摆放网格；构件按 1m 网格 | 24 地块 = 一个可读的城；建筑不跨地块 |
| 坐标系 | 右手系；模型正面朝 +Z | 避免引擎导入后集体转 90° |
| 轴心 | 建筑在底面中心；道具在重心；角色在双脚中间 | 摆放与动画不出错 |
| 引擎 | 引擎无关的 glTF 2.0 / USD 交付 | 不被单一引擎绑死 |
| 纹理 | PBR Metallic-Roughness；2K 主资产、1K 道具、512 群众 | 包体与显存 |
| 光照 | 单向光 + 天空光 + 点光（灯）；不烘焙死 | 昼夜与寒潮要动态 |
| 目标帧率 | 全城视角 30fps（中配）、街区视角 60fps（高配） | 斜俯视要能拉近 |

## 八、命名与 ID

```text
bld.<type>.<tier>.<lod>        例：bld.greenhouse.t2.lod0
bld.<type>.damage.<part>       例：bld.greenhouse.damage.roof_b
env.<biome>.<element>          例：env.grayharbor.ground_snow
chr.<characterId>.<lod>       例：chr.wenyuan.lod0
chr.crowd.<archetype>.<variant>
prop.<group>.<name>.<variant>  例：prop.medical.crate_supply.a
veh.<type>.<variant>           例：veh.hauler.tracked
vfx.<category>.<name>          例：vfx.weather.blizzard
ui.<kind>.<name>               例：ui.icon.heat
```

规则：

- 全小写、点分层、连字符分词；不用中文、不用空格、不用版本号。
- `characterId` = 姓名拼音（`wenyuan`、`cenyan`、`zhuifeng`）。**不要按 `agentId` 去前缀机械推导**：玩家派支持者的 `agentId` 是 `npc-<拼音>`，AI 党魁与外域是 `<factionId>`；映射见 [canon §13.4](../world/canon.md#134-角色与建筑)。`model.json` 同时记录 `agentId` 与 `characterId`。
- 派系资产用**资产 slug**（`grayharbor-commune` 等），不要用 `factionId`（`human-neutral`）或 `seatId`（`seat.commune`）；三者的映射只在[速查表](../world/canon.md#131-派系与席位)维护。
- 同一资产的 LOD 必须同前缀，只改 `.lodN`；变体用 `.a/.b/.c`。
- 交付目录按域分：`buildings/`、`characters/`、`props/`、`vehicles/`、`environments/`、`vfx/`、`ui/`、`audio/`。
