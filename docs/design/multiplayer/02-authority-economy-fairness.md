# 权威、经济与公平

> 本页定义多人世界里「谁说了算、钱怎么花、怎么防止有人把桌子掀了」。
> 上游：[多人总纲](README.md) · [席位与时钟](01-seats-and-clock.md)

## 一、权威分层

多人版的权威只有一条线：**世界权威在服务端，解释权在 Agent，可见性由投影决定，客户端只提交意图。**

| 层 | 拥有 | 不能做 |
|---|---|---|
| 世界权威（服务端） | 资源、库存、通行、时钟、伤势、合同、行动结果、投票结果 | 不解释、不写台词、不替 Agent 决策 |
| Agent（AI 或真人） | 感知后的解释、记忆、选择、协商、提案、台词意图 | 不直接写世界状态；一切副作用经命令网关 |
| 投影（per-seat） | 按席位裁剪的可见世界 | 不做业务判断；不隐藏公共事实 |
| 客户端 | 渲染、输入、预测性提示 | 不推进时钟；不写存档；不决定结果 |
| 运营/导演 | 外域意图、时代任务、事件注入、仲裁 | 不改玩家库存、不改投票结果、不伪造证据 |

三条硬约束：

1. **命令网关唯一入口。** 任何改变世界的行为必须是一条 `command`；没有「直接改数据库」的管理员操作，运营也不例外（运营用 `ops.*` 命令，同样留痕）。
2. **投影不是权限。** 权限在服务端裁决；投影只是「不把不该看的发给你」。两者都要有，缺一不可。
3. **结果不可预测。** 客户端可以显示「预计到达」「预计产出」，但不得用本地推算替代服务端结算。

## 二、投影：谁看到什么

多人最容易泄露的不是密码，是「别人不该知道的事」。投影按**知识来源**裁剪，而不是按「是不是好友」。

| 信息 | 同席 | 其他席位 | 观战 | 依据 |
|---|---|---|---|---|
| 城市仪表（热、粮、水、病、不满） | 全部 | 全部 | 全部 | 公共读数 |
| 议事记录、法案文本、投票 | 全部 | 全部 | 全部（延迟 5 分钟） | 公开 |
| 承诺账本 | 本席全部；他席只看到「与本席有关」的条目 | 同左 | 不显示 | 当事人原则 |
| 本派 8 人态势与理由 | 全部 | 不可见 | 不可见 | 私事 |
| 他派 8 人的名单与岗位 | 不可见 | 不可见 | 不可见 | 与单人一致：只能通过会面痕迹、公开言论、传闻知道个别成员 |
| 他派 8 人的态势/理由 | 不可见 | 不可见 | 不可见 | 私事 |
| 库存明细 | 本派仓全部；公库按授权 | 公库公开总量，明细需审计权 | 总量 | 权限 |
| 队伍位置 | 本派队伍 | 公开道路上可见；隐蔽行动不可见 | 公开层 | 感知 |
| 会面事实 | 本派参与 | 公开/半公开场所可见；私下需监视 | 公开层 | 会面痕迹 |
| 会面内容 | 参与双方 | 不可见 | 不可见 | 隐私 |
| 私聊文本 | 参与双方 | 不可见（仅仲裁库） | 不可见 | 隐私 |
| 外域真实意图 | 不可见 | 不可见 | 不可见 | 只能推断 |
| 导演指令原文 | 不可见 | 不可见 | 不可见 | 只给痕迹 |

**一条容易写错的规则：公开不等于实时。** 中继降级时，异地信息 +1 至 +3 小时；中断时只有同节点即时。多人版把这个规则用在玩家之间：跨城区的私下消息也要按中继规则延迟，否则「通信」这个系统就没有意义。

## 三、共享经济

五人共用一个公库，是本作多人最有张力的地方，也是最容易被打穿的地方。

### 三条线不能混

| 线 | 归属 | 谁能动 | 多人风险 |
|---|---|---|---|
| 城市公库 | 全城 | 预算、委托、工务/公社授权 | 一席在被吞并前搬空 |
| 派系仓 | 各派 | 本派党魁 | 用派系仓绕过公库监管 |
| 在建工地预留 | 项目 | 项目授权人 | 重复预留、一料多诺 |

### 转移与审批

| 动作 | 门槛 | 记录 |
|---|---|---|
| 公库 → 本派仓，≤ 20 单位/日 | 岗位授权 | 流水，公开总量 |
| 公库 → 本派仓，21–40 单位/日 | 预算案（3 票）或轮值议长签发 | 流水 + 议事录 |
| 公库 → 本派仓，> 40 单位/日 | 禁止；只能拆成两日、各走一次预算案 | — |
| 公库 → 他派仓，单笔 ≤ 20 | 预算案（3 票）+ 公开理由 | 议事录 + 审计 |
| 派系仓 → 公库 | 自由 | 流水 |
| 派系之间交易 | 双方确认 + 流水；单笔 ≤ 20 | 私下内容不公开，总量公开 |

**单日单席上限 = 40 单位**（按资源种类分别计，不合并计算）。寒潮与白障期间上限降为 **20**，且 21 以上一律要 **4 票紧急预算**：危机时刻不允许有人把仓库搬空。

> 为什么不用「产出 × 百分比」：材料日产出只有 18 左右，30% 不到 6，会把 20 单位的岗位授权档直接变成死条文。固定上限 40 与三层审批能对上，也更容易在界面上解释。

### 反洗劫

三种典型打法与对策：

| 打法 | 表现 | 对策 |
|---|---|---|
| 临吞并前搬空 | 表决前 24 小时连续大额转移 | 提案进入议程后，涉事席位的大额转移自动冻结至表决结束 |
| 一料多诺 | 同一批材料答应给三个工地 | 预留即锁定；同一物料不能重复预留；界面显示共享回执 |
| 低价互送 | 两席用明显不对等价格互送资源 | 交易价格偏离基准价 3 倍以上进入审计条目；连续 3 次公开 |

审计条目不是惩罚，是**公开记录**：谁都能看到「某席在表决前把 38 单位材料转进了自己仓里」。政治后果由其他席位决定，不由系统判罚。

## 四、模型预算：人多不等于烧钱

单人版 15 个 Agent 的实际模型调用是「每日 3–5 个关键决策」。多人版必须守住同一个量级，否则五人局成本是单人的数倍。

### 总预算守恒

| 项 | 单人 | 多人（5 席） |
|---|---:|---:|
| 每游戏日关键决策上限 | 5 | **18（5 人局）–24（2 人局）** |
| 硬上限（含议事周峰值） | 8 | **36** |
| 外域决策 | 3 | 3（不随席位数增加） |
| 人类玩家 | 1（不调用） | 5（不调用） |
| AI 补齐席位 | — | 每个空席 +2（AI 党魁），计入上限 |

多人不是「5 × 15 个 Agent」，而是**把同一份注意力预算分给五个席位**。规则如下：

1. 每席每日最多 **3 次**支持者推理（请愿、挖角、背叛、关键执行），对应每日最多 3 名「活跃支持者」；其余 5 人由规则结算，不调用模型。
2. 外域三席共享 **3 次/日**，按事件优先级排队。
3. 议事周额外 **≤12 次**（辩论、表态、拉票回应），硬上限 36。
4. 超预算时按优先级降级：先降「闲聊/安慰」，再降「例行报告」，最后降「非关键谈判」；被降级的请求写入日志并标注 `degraded`，不假装做过。
5. **AI 补齐席位不额外加预算**：它替代的是人类席位，不是新增派系。

### 降级不能变成欺骗

降级时必须满足三条：

- 玩家能看到「这条回应由规则生成」的标记；
- 规则生成的承诺不进入账本（只有模型决策才能签）；
- 关键决策（吞并、宣战、驱逐、死亡）永不由降级路径处理。

## 五、公平

### 什么算公平

本作的公平不是「五派一样强」，而是**每一席都有活路，且失败可解释**。

| 维度 | 目标 | 度量 |
|---|---|---|
| 生存 | 每席存活季数中位数差 ≤1 季 | 赛季结算 |
| 参与 | 每席每周至少 1 次有效提案或附议 | 议事记录 |
| 影响力 | 每席至少参与 1 次通过的宪制法案（提案/附议/关键票） | 议事记录 |
| 失败可解释 | 被吞并前 7 日内至少有 2 个可观察前兆 | 事件日志 |
| 不付费获胜 | 付费项不含资源、票数、影响力 | 商城清单 |

### 反雪球

单人版已有「反向联盟」「4 票宪制」「庇护」三道闸；多人版追加三道：

- **连续主导惩罚（多人追加）**：同一席连续两周主导议程，其他四席相互关系 −5，且该席下一次提案的附议门槛 +1（需要 2 席附议）。单人版只有前半条（AI 关系 −5），因为单人没有「附议」这一步。
- **多数派疲劳（多人追加）**：同一组三席连续三周以相同的赞成组合通过法案，从第四次起全城不满 +5/周、这三席民意支持各 −2；如果当周供暖、粮食或疾病指标确实改善，减半。理由：三个人可以合法主导，但「固定三人组」不能是免费的。
- **弱者议程权**：民意支持最低的席位每季有 3 次「优先议程」，用于把对自己最重要的案排进前三项。

### 不对称不是不公平

五派开局支持、基石、地块、8 人班子都不同，这是设计。多人版只做一次零和重分配（见[席位与时钟](01-seats-and-clock.md#九席位平衡补偿)），不做「每派发一样的东西」。把五派做成对称的，等于把政治做成选皮肤。

## 六、反作弊与反破坏

### 威胁模型

| 威胁 | 谁做 | 检测 | 响应 |
|---|---|---|---|
| 客户端改资源 | 作弊工具 | 服务端权威 + 命令校验；客户端数值不参与结算 | 拒绝命令；异常账号标记 |
| 重放命令 | 抓包重发 | `commandId` 幂等 + `controllerEpoch` | 丢弃；累计触发复核 |
| 多开代打 | 一人两席 | 设备/网络指纹；行为相似度（同一秒内两席提交） | 标记、警告、赛季封禁 |
| 串通刷分 | 两席互送 | 交易偏离基准 3 倍；连续互送 | 审计条目公开；赛季结算剔除异常局 |
| 恶意拖局 | 单席 | 连续两周末提交命令 | 自动托管 → 弃席 |
| 引怪害人 | 单席 | 紧张度上升与目标分布 | 袭击目标按规则选；紧张上升公开 |
| 观战泄密 | 观战者 | 观战延迟 + 排位关观战 | 取消观战资格 |
| 私聊诈骗 | 玩家 | 举报 + 仲裁库 | 承诺不进账本即无强制力；屡犯限制私聊 |

### 三条不做的反作弊

- **不做客户端反外挂内核**：本作是回合/ticks 制，服务端权威足够；侵入式反作弊与「研究装置」的定位冲突。
- **不做行为评分惩罚**：不因为玩家「太激进」降权；政治后果由其他玩家给。
- **不做自动封号**：只做标记与人工复核，避免误杀长局玩家。

## 七、运营

### 世界生命周期

| 阶段 | 时长 | 做什么 |
|---|---|---|
| 开季 | 第 1 日 | 冻结世界种子、席位、规则版本；公布时代任务 |
| 进行 | 1–4 季 | 每周议事；每季末寒潮；导演按预算下指令 |
| 结算 | 季末 | 编年史、席位统计、异常审计汇总 |
| 续局 | 季末 | 可开遗产局（同一座城）或新世界 |
| 归档 | 赛季结束 | 世界只读；回放与编年史可查 |

### 仲裁

- 只处理三类：作弊、骚扰、规则歧义。
- 仲裁依据是事件日志与命令记录，不是聊天截图（截图可伪造，日志不可）。
- 仲裁结果进入「判例库」，用于下一版规则澄清；**不追溯改历史**。

### 回放

服务端保存 `worldSeq` 全量事件，可按席位视角回放。回放用于：争议复核、内容创作、研究对比、Bug 复现。回放不包含私聊内容，除非进入仲裁流程。

## 八、指标

| 类别 | 指标 | 健康区间 | 说明 |
|---|---|---|---|
| 参与 | 每席每周有效命令数 | 8–25 | 过低=没事做；过高=微操 |
| 参与 | 议事参与率（提案/附议/发言/投票） | ≥80% | 低于 60% 说明议事无意义 |
| 政治 | 吞并/政变发生率（每季每席） | 15%–35% | 0 = 没有压力；>50% = 过于残酷 |
| 政治 | 宪制法案通过率 | 20%–40% | 太高说明门槛失效 |
| 稳定 | 托管率（席位时间占比） | ≤15% | 高于 25% 说明节奏或体验有问题 |
| 公平 | 席位存活季数中位数极差 | ≤1 季 | 超过 2 季要查补偿 |
| 成本 | 每世界每日模型决策数 | 18–24 | 超过 36 必须降级 |
| 体验 | 回归玩家次日留存 | ≥50% | 托管后回来的人还愿不愿意玩 |

## 九、Demo 必须留的接口清单

| 接口 | 形状 | 单人怎么落 |
|---|---|---|
| `seatId` | 所有命令/事件/投影字段 | 固定为所选席位的短名（`seat.commune` 等） |
| `actorId` | 每条命令/事件的实际行动者：AI 党魁与外域用 `factionId`，玩家派支持者用 `npc-<拼音>` | 单人也记录，便于回溯「是谁做的」 |
| `controllerType` | `human \| ai \| stand-in \| vassal \| vacant` | 单人 `human`；AI 派系 `ai` |
| `controllerEpoch` | 单调递增 | 单人恒为 1 |
| 投影过滤器 | `project(event, seatId) -> view` | 单人也过滤，只是只有一个视角 |
| 命令网关 | `submit(command) -> accepted \| rejected(reason)` | 单人也走，便于回放 |
| 时钟服务 | 服务端唯一 `worldTick` | 单人可暂停/加速，仍由服务端发 tick |
| 事件日志 | append-only + `worldSeq` | 单人也记录，用于编年史 |
| 转移审计 | 大额转移写审计条目 | 单人也记录，用于「公开账本法」 |
| 预算计数器 | 每席/全局模型决策计数 | 单人也计数，用于成本观测 |

**验收方式：** 用单机跑一局，导出事件日志，写一个脚本按「假想的五个 seatId」重放——如果任何一条事件无法归属到席位，或任何一次投影需要读全局状态，就说明接口没留够。

## 十、设计护栏

| 风险 | 护栏 |
|---|---|
| 服务端被绕过 | 命令网关唯一入口；客户端不参与结算 |
| 投影泄露 | 按知识来源裁剪；公开层延迟；私聊不进投影 |
| 公库被搬空 | 单日上限；提案期冻结；审计条目公开 |
| 模型成本爆炸 | 总预算守恒；每席上限；优先级降级；降级可见 |
| 强者恒强 | 反向联盟、连续主导惩罚、弱者议程权、4 票宪制 |
| 作弊误判 | 只标记不自动封；人工复核；判例库 |
| 运营越权 | `ops.*` 命令同样留痕；不改库存与投票结果 |
| 规则歧义 | 仲裁只解释，不追溯改历史 |
