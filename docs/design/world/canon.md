## 3. 议事会（五席）

| 项 | 规则 |
|---|---|
| 席位 | 5：每派 1 票；玩家是**本派党魁**，自己决定本派那一票 |
| 普通法案 | 3/5 通过 |
| 宪制法案 | 4/5 通过：吞并、修宪、紧急状态、宣战、改变中继最高控制权、驱逐一个派系、改变票制 |
| 程序动议 | 3/5：加议程、延后、听证、休会 |
| **计票口径** | **门槛是绝对票数，不随弃权下降**：普通法案至少 3 张赞成票，宪制法案至少 4 张赞成票。弃权与缺席只减少反对票，不降低门槛；因此 2 赞成 + 3 弃权仍为失败，两派永远不能单独决定全城 |
| 议程 | 轮值议长每周定 3 项；任何一派可用 3 票程序动议加 1 项 |
| 轮值议长 | 每周轮换；可被 3 票撤换；议长保留本派投票权 |
| 提案 | 每派每周最多 1 项正式提案；未进议程的案不能表决 |
| 表决时点 | 每周第 7 日 00:00（t144、312、480…） |
| 承诺期限 | 1–14 日；违约：信任 −15、民意支持 −5、相关支持者 −1 档、下次要价 +1 |
| 执行 | 由本派 8 名支持者代表按分管领域执行；执行度由具体执行者的态势与能力决定 |
| 旁听 | 议事公开；私下会谈不公开；会面事实可见，内容不可见 |

## 4. Agent 编制

### 实例化规则

- **每局同时激活 15 个 Agent**，不是 20 个。
- 玩家选哪一派，就实例化该派的 **8 名支持者代表**（不含玩家；玩家是本派党魁）。
- 其余四派各实例化 **1 名党魁**（共 4 人）。
- 三个非人势力各实例化 **1 名最高决策者**（共 3 人）；该 Agent 就是本势力的最终决定者。
- 8 + 4 + 3 = 15。
- **多人局例外**：40 名支持者 + 3 名外域 + 空席 AI 党魁 = **43–46 个具名 AI 身份**（5 人局 43、2 人局 46），但每席只有 **3 名「活跃支持者」**进入模型推理，其余由规则模拟；详见[席位与时钟](../multiplayer/01-seats-and-clock.md)与[权威、经济与公平](../multiplayer/02-authority-economy-fairness.md)。「15」是单人局的实例化上限，不是多人局的上限。
- 其余具名成员在名册中，不参与本局日常推理；他们作为「抽象支持者」影响该派党魁的合法性。
- 普通工人不是 Agent：由规则模拟，按班组分配、产出、伤亡。

## 5. 支持与吞并

> **两个「支持」不是一件事，全文必须分开写：**
> - **民意支持（% ）**：全城层面，五个派系各有 0–100% 的相对支持度（开局 29/22/20/17/12），影响动员力、党魁合法性与吞并风险。旧稿的「支持 −5」一律指这一项。
> - **支持态势（五档）**：玩家本派 8 名支持者代表对玩家的私人判断（坚定/观望/动摇/离心/敌对）。旧稿的「支持 −1 档」指这一项。
> 两者不互相换算，也不能相加。

### 支持态势（五档）

| 态势 | 含义 | 玩家能看到 |
|---|---|---|
| 坚定 | 愿意为你承担风险 | 「他站你这边」+ 一条理由 |
| 观望 | 还没决定，看你接下来做什么 | 「他还在看」+ 一条理由 |
| 动摇 | 开始考虑别的选项 | 「他最近和砾火的人走得很近」 |
| 离心 | 已经在为自己找后路 | 「他把家属送去了外环」 |
| 敌对 | 主动反对你，可能已经答应别人 | 「他在公开场合质疑你的投票」 |

- 支持态势由 AI 判断，不由单一数值阈值决定。
- 判断输入：**信念契合、利益、关系、恐惧/压力、外部诱惑、希望**。
- 每次变化必须有理由；理由进入玩家的「人物册」与「本周账本」。
- 玩家不能直接看到精确分数；研究控制台可以，但玩家界面不显示。

### 吞并四阶段

| 阶段 | 谁在做什么 | 玩家能看到 | 玩家能做什么 |
|---|---|---|---|
| 1. 试探 | 其他派系评估你的弱点、城市局势、自己的风险 | 使节试探、公开嘲讽、报价变硬 | 修补关系、展示实力、找庇护 |
| 2. 挖角 | 对手私下接触你的 8 人，给出条件 | 会面痕迹、请辞、工作拖延、公开抱怨 | 询问、监视、加薪/升职、驱逐、兑现承诺 |
| 3. 提案 | 对手在议事会提出「吸收/庇护/托管」案（宪制 4/5） | 议案文本、附议者、表决倒计时 | 拉票、交易、揭露、反提案、找第三方保护 |
| 4. 表决/政变 | 4/5 通过，或 ≥5 名支持者公开倒戈 | 表决板、街头反应、最后通牒 | 最后辩论、承诺、庇护、接受结局 |

- **不是 `support < X` 自动触发。** AI 是否进入下一阶段，取决于机会、风险、关系、历史与自身合法性。
- **开局 14 天保护期**；同一派系两次尝试之间至少 7 天。
- **宪制 4/5**：吞并需要四派同意，任何单一派系无法合法吞并你。
- **庇护**：一派可以给你庇护（3/5），通过后 1 季内针对你的吞并提案需要 5/5；代价是让渡一项政策/资源，可能沦为附庸。**庇护不自动续期**：第二次要价 +1 档，连续两季接受同一派庇护即转为附庸（宪制表决须与其一致）。
- **竞争性保护**：两个派系同时想吞并你时，它们会互相牵制；玩家可以利用。
- **失败**：4/5 吞并案通过，或 ≥5 名支持者公开倒戈/离开且无人庇护，玩家失去党魁身份 → 本局结束，进入「被吞并」结局与编年史；城市继续存在，可开「遗产局」以新身份回到同一座城。
- **支持崩解**：按 8 个席位计算（空缺=无支持），≥5 个席位处于「离心/敌对/空缺」且无庇护，本派失去合法性；其他派系可以提出吞并（宪制 4/5）或支持政变。**没有正式的内部信任表决**；玩家不是被投票赶下台，而是被抽走了支持。
- **死亡与补位**：Agent 永久死亡。接任者以独立身份进入岗位，候选来源与空缺期见 [15-raids-and-repair.md — 袭击、死亡与修复](../gameplay/15-raids-and-repair.md)。

### 地块与热级

- 24 个地块：核心 6、内环 6、外环 6、边环 6；每块一座建筑，三级。
- **建筑共 29 类**（表格见[城建与供热](../gameplay/08-city-building.md#建筑表)）：28 类地块建筑（24 类基础 + 居所/密集居所/收容所/广场）+ 中继炉；中继炉本身不占地、不升级、不可拆。
- 可升级建筑 28 类 × 3 级 = 84 个建筑形态；中继炉为固定地标。
- 热级 = 中继基础 + 环带修正 + 热站 + 保温 − 寒潮；截断 0–4。
- 中继基础：通信优先 1、均衡 2、供热优先 3；能耗 8/12/16 每日；远程延迟 0/+1/+2 tick；中继日损 0/−1/−2。
- 环带修正：核心 +2、内环 +1、外环 0、边环 −1。
- 热站覆盖相邻 3 格，3 能源/日；保温 +1，8 材料一次性。
- 寒潮 −2，持续 3–5 日；白障 −3，持续 5–7 日。

### 建筑三态

| 状态 | 产出 | 修复 | 说明 |
|---|---|---|---|
| 完好 | 100% | — | 正常 |
| 受损 | 50% | 材料 = 建造成本 × 30%，工期 = 成本 ÷ 10 + 2h | 热需 +1；住宅受损会让住户生病 |
| 损毁 | 0% | 材料 = 建造成本 × 70%，工期 = 成本 ÷ 10 + 4h | 住宅损毁会死伤住户；需先清墟 |

## 7. 袭击与伤亡

| 项 | 规则 |
|---|---|
| 触发 | 边境紧张 >60、白障、导演指令、外域报复、玩家违约 |
| 目标 | 边环/外环建筑、道路车队、哨塔、巡逻队；优先无防御、低热级、靠近外域的目标 |
| 伤害 | 建筑受损/损毁；工人死亡 1–8 人；在场 Agent 受伤（48h）或死亡（永久，触发补位） |
| 防御 | 防风墙、哨塔、训练场、民兵巡逻、疏散演练；每项降低伤亡/损毁 |
| 预警 | 哨塔/侦察/追风/青枝/洛的提醒；无预警时伤亡 +50% |
| 修复 | 需工程队 + 材料 + 时间；修复期间产出减半；损毁需先清墟 |
| 政治后果 | 死亡名单进入简报；支持者会追责；对手会在议事会质询；修复承诺进入账本 |

|---|---|
| 1 tick | 1 游戏小时 |
| 1 日 | 24 tick；默认 **20 秒/tick**；1 日 = 8 分钟 |
| 1 周 | 7 日 = 168 tick；1 周 ≈ 56 分钟 |
| 1 季 | 28 日 = 672 tick；1 季 ≈ 3 小时 44 分 |
| 对话 | **单人**：对话开始时自动暂停；结束恢复；读条款/写承诺不限时。**多人**：世界不停，对话转为异步消息与「议事周窗口」，见[多人体系](../multiplayer/01-seats-and-clock.md) |
| Agent 主行动 | 每 Agent 每日 1 次；事件触发，不逐 tick 推理 |
| Agent 社交行动 | 每 Agent 每日 1 次；可与主行动合并 |
| 请愿 | 每日最多 2–3 个上桌；其余进简报 |
| 表决 | 每周第 7 日 00:00 |
| 寒潮 | 每季末 3–5 日；白障只在第 4 季，5–7 日 |
| 离线 | **单人**：断开 60 秒自动暂停，不补算。**多人**：不暂停，转 AI 托管；超过托管上限按「缺席」处理 |

## 11. 多人（设计层）

- 模式：**同城共治**。1–5 名人类各占一个派系席位，空席由 AI 党魁补齐；不是各建一城，也不是 MMO。
- 权威：服务端唯一权威；客户端只提交命令，不写世界状态。
- 时钟：两种会话——同步长局（一季 4 场，约 3–4 小时；15 秒/tick）与异步长局（真实时间推进，议事周为同步窗口；12 分钟/tick）。
- 界限：Demo **不实现联机**，但命令、投影、存档必须带 `seatId`，以便后续接入。
- 五人局开局民意重分配（零和，规则不变）：公社 25%、砾火 22%、地生 21%、止戈 18%、远星 14%。2–4 人局插值，余数给最低支持席。
- 细节：[多人总纲](../multiplayer/README.md) · [席位与时钟](../multiplayer/01-seats-and-clock.md) · [权威、经济与公平](../multiplayer/02-authority-economy-fairness.md)

## 12. 资产（设计层）

## 13. ID 对照表

### 13.3 道路

16 条道路的 `roadId` 以[灰港城与地图](grayharbor.md#十六条道路)表为准，不另起别名。命名的规律是两端 `nodeId` 缩写：`r-gh-wg` = grayharbor—watergate，`r-ps-fx` = pass—windgap，依此类推。

### 13.4 角色与建筑

- **内容包 `agentId` 按身份类型取三种写法：**
  - 玩家派支持者：`npc-<拼音>`，示例 `npc-wenzhao`、`npc-luchen`；
  - AI 党魁：`<factionId>`，示例 `human-independent`（显示名岑雁）、`human-neutral`（显示名闻昭，玩家不占席时）；
  - 外域 Agent：`<factionId>`，示例 `species-fauna`（显示名追风）。
- **未上场成员的内容引用**使用 `npc-<拼音>`，例如沈砾 `npc-shenli`。引用按具名名册解析，可用于署名、传闻等静态内容。上场与命令权限由运行名册和授权决定。见 [roster.md — 具名名册](../characters/roster.md)。
- **资产 `characterId` 使用姓名拼音**，示例 `wenzhao`、`cenyan`、`zhuifeng`。为 AI 党魁或外域 Agent 绑定资产时，使用其运行中的派系 ID，避免为同一人物登记第二个 Agent。
- `bldId` 见[资产清单](../assets/01-inventory.md#一建筑)；示例：`council-hall`、`greenhouse`、`watchtower`。
- 建筑引用一律写 `bld.<bldId>`，节点引用写 `node.<nodeId>`，道路引用写 `road.<roadId>`。

### 13.5 同一个人物的四种写法

以灰港公社的闻昭为例，同一条身份链在不同层有四套标识。**它们不是别名，各自只在一个层里有效。**

| 层 | ID | 用在哪 | 谁创建 |
|---|---|---|---|
| 席位 | `seat.commune` | 多人席位、命令、投影、存档 | 房间/开局 |
| 派系 | `human-neutral` | 内容包、外交、地图道路控制、AI 党魁 | 内容包 |
| AI 党魁 | `agentId = human-neutral` | 玩家不选公社时，作为该派战略 Agent | roster |
| 人物 | `npc-wenzhao`（内容包）/ `wenzhao`（资产） | 立绘、3D、人物册、请愿、执行 | 内容包/资产 |

规则：

1. **玩家占席时，该派的 AI 党魁不创建。** 名册第 1 行以 `npc-wenzhao` 存在，身份是「资深支持者」，不是「前党魁」。
2. **同一个人物不能同时在两个 ID 下行动。** 不允许 `human-neutral` 和 `npc-wenzhao` 同时出现在议事厅。
3. **日志中的席位与动作者分开记录。** `actorId` 可以是 `player-1`（玩家）、`human-neutral`（AI 党魁）或 `npc-wenzhao`（支持者），三者行动时都可归属 `seat.commune`。外域和系统也是事实来源，其归属规则见 [02-authority-economy-fairness.md — Demo 席位接口](../multiplayer/02-authority-economy-fairness.md#九demo-必须留的接口清单)。
4. **改名不改 ID。** 显示名可以随版本改；ID 改动必须升 `contentVersion` 并写迁移。
